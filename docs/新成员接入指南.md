# 新成员 / 新设备接入指南（如何修改本项目并提交到远程仓库）

> 仓库：https://github.com/grf01m203/cyn-j-idea （**当前为公开仓库**：任何人都能克隆，但**只有被邀请的协作者才能 push**）
> 远程地址（SSH）：`git@github.com:grf01m203/cyn-j-idea.git`
> 默认分支 `master`，主分支 `main`，集成分支 `develop`，标签 `v0.1.0` / `v0.2.0`

---

## 0. 先明确三件事

| 问题 | 答案 |
|---|---|
| 别人能改我的项目吗？ | **能，但只能通过仓库**：被加为 Collaborator → clone → 改 → push / PR。直接改你电脑上的文件不算协作，也不会有他的提交记录。 |
| 公开仓库有风险吗？ | 代码任何人可见；不想公开就去 Settings → General → Danger Zone → 改成 Private（协作者仍可访问）。 |
| 会不会覆盖我的代码？ | 只要按「分支 + PR + 先 pull 后 push」的流程走就不会；**禁止**在 `main` 上直接强推（force push）。 |

---

## 1. 仓库所有者先做（陈以诺）

1. **邀请协作者**：仓库 → Settings → Collaborators → *Add people* → 输入对方 GitHub 用户名 → 对方在邮件/GitHub 通知里接受。
2. **（建议）保护主分支**：Settings → Branches → Add branch protection rule → 分支填 `main`：
   - ✅ Require a pull request before merging（≥1 次 approval）
   - ✅ Do not allow force pushes
3. **（可选）改为私有**：Settings → General → 最下方 Danger Zone → Change visibility。

## 2. 新成员首次接入（对方设备上执行）

### 2.1 安装并配置 Git

```bash
# 安装 Git for Windows 后，配置本人身份（必须与 GitHub 账号一致！）
git config --global user.name  "张三"
git config --global user.email "zhangsan@example.com"
```

> ⚠️ 身份必须是**本人**且邮箱已在 GitHub 验证，否则提交不会归属到他的账号，"每人有提交记录"这项会失分。

### 2.2 选择认证方式（二选一）

**A. SSH（推荐，一次配置长期免密）**

```bash
ssh-keygen -t ed25519 -C "zhangsan@example.com"     # 一路回车即可
cat ~/.ssh/id_ed25519.pub                            # 复制输出的公钥
```

把公钥粘贴到 GitHub → Settings → SSH and GPG keys → New SSH key，然后验证：

```bash
ssh -T git@github.com      # 出现 "Hi 用户名! You've successfully authenticated" 即成功
```

> 若 22 端口被校园网封，在 `~/.ssh/config` 加：
> ```
> Host github.com
>   Hostname ssh.github.com
>   Port 443
>   User git
> ```

**B. HTTPS + Personal Access Token（临时用/不方便配 SSH）**

GitHub → Settings → Developer settings → Personal access tokens →
- Classic：勾选 `repo`
- 或 Fine-grained：仓库选 `cyn-j-idea`，权限 `Contents: Read and write`

克隆时用户名填 GitHub 用户名，**密码填这个 token**（不是账号密码）。

### 2.3 克隆仓库

```bash
git clone git@github.com:grf01m203/cyn-j-idea.git          # SSH
# 或
git clone https://github.com/grf01m203/cyn-j-idea.git      # HTTPS
cd cyn-j-idea
```

### 2.4 配置本项目的本地依赖与凭据

```bash
# 后端 OSS 凭据（每个开发者自己填，绝不提交）
cp campus-venue-server/config/oss.env.example campus-venue-server/config/oss.env
# 编辑 oss.env：填 OSS_AK / OSS_SK（可向组长要），填完确认 git status 里看不到它

# 数据库（本机 MySQL 8）
mysql -uroot -p < docs/sql/V1__init.sql
mysql -uroot -p < docs/sql/V2__seed.sql

# 后端 / 前端启动方式见根目录 README.md
```

## 3. 日常修改 → 提交 → 推送（每个功能点一遍）

```bash
# 1) 同步最新集成分支
git checkout develop
git pull --rebase origin develop

# 2) 建自己的功能分支（一人一分支，禁止交叉提交）
git checkout -b feature/venue-zhangsan

# 3) 改代码，然后提交
git add <改动的文件>
git commit -m "feat(venue): 新增场地开放规则批量维护"

# 4) 推送到远程
git push -u origin feature/venue-zhangsan
```

然后到 GitHub 上开 **Pull Request**：`feature/venue-zhangsan` → `develop`，填写：
- 做了什么
- 如何自测（命令/截图）
- 影响范围（表/接口）

由至少 1 名成员 Review 后合并。

## 4. 合并进稳定分支（由组长或指定人执行）

```bash
git checkout main
git pull
git merge develop            # 或通过 PR 合并
git push origin main
git push origin main:master  # 同步默认分支 master（本仓库约定：master 与 main 内容一致）
```

## 6. 常见报错与处理

| 报错 | 原因 | 处理 |
|---|---|---|
| `Permission denied (publickey)` | SSH key 没配好/没加到 GitHub | 重做 2.2A；`ssh -vT git@github.com` 看细节 |
| `remote: Permission to ... denied` | 不是协作者 / token 无 `repo` 权限 | 让组长邀请；或换有权限的 token |
| `! [rejected] ... non-fast-forward` | 远程有新提交，本地落后 | `git pull --rebase` 后重推（**不要** `push -f` 到 main） |
| `CONFLICT (content): Merge conflict in ...` | 两人改了同一处 | 打开文件解决 `<<<<<<< ======= >>>>>>>`，`git add` 后 `git rebase --continue`（或 `git merge --continue`） |
| `fatal: not a git repository` | 拷了源码却没拷 `.git` | 重新 clone；或把整个目录（含 `.git`）一起拷贝 |
| 换行符整文件 diff（Windows/Linux） | CRLF/LF 差异 | 已由 `.gitattributes` 统一；仍异常时执行 `git add --renormalize .` |
| 误把 `node_modules` 加进去了 | 手动 `git add -f` | `git rm -r --cached node_modules`，确认 `.gitignore` 生效后重新提交 |
| 误提交了 `oss.env` | 手动强加 | 立刻 `git rm --cached` 并轮换 OSS AccessKey（凭据已泄露视为失效） |

## 7. 纪律（直接影响评分）

1. **每人用自己的 GitHub 账号提交**，严禁一人代所有人提交。
2. 每人在自己的 `feature/<模块>-<姓名拼音>` 分支开发，通过 PR 合并，**每人每周 ≥3 次有意义的提交**。
3. 提交信息用 Conventional Commits：`feat/fix/docs/refactor/test/chore(scope): 说明`。
4. **不提交**：`node_modules/`、`dist/`、`target/`、`*.log`、`data/`、`config/oss.env`、`application-prod.yml`。
5. 改动前先 `git pull --rebase`，改完先自测（`mvn test` / `npm run build`）再 push。

## 8. 另一种"直接改我电脑上的文件"的方式（不推荐，仅临时）

- **远程桌面**（Windows 远程桌面 / 向日葵 / AnyDesk）→ 对方直接操作本机，提交仍发生在本机账号下。
- **局域网共享文件夹** → 同上，且无版本历史。
- **VS Code Remote-SSH** → 需在本机启用 OpenSSH Server 并建账号，配置较重。

> 以上方式都**不会**在 GitHub 上留下对方自己的提交记录，正式协作请用第 2~5 节的仓库流程。
